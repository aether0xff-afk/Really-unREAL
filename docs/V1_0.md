# Really-unREAL v1.0 contract

Version 1.0 is the first stable **simulation-core** release. It is not a claim
that a human being can be perfectly reconstructed, and it is not an automatic
impersonation product.

## What 1.0 guarantees

### Observable behavior, not hidden psychology

The system models observable communication only: silence, timing, reply/follow-up
behavior, message splitting, language style, topic continuity, and explicitly
mentioned events. It does not produce affection, attraction, intent, diagnosis,
or hidden-thought scores.

### Two first-class twin modes

- `PERSON`: reproduce another explicitly mapped person's observable behavior.
- `SELF`: reproduce the user's own communication behavior across relationships.

SELF mode uses the same replay contract as PERSON mode, but relationship-specific
persona and timing may override global fallbacks when enough evidence exists.

### Leakage-safe Historical Replay

Training/validation/test are chronological. Kakao minute timestamps are treated
as intervals. Long-gap REPLY-vs-INITIATE roles may be marked ambiguous rather
than forced into a false label. Generation receives no held-out target response.

### Closed-loop Shadow Simulation

A past interval can be replayed with target-authored future messages hidden.
Counterpart messages remain exogenous observations; simulated target messages are
fed into subsequent simulated context. Real future target messages are used only
afterward for scoring. Event matching is time-window bounded so wildly mistimed
predictions do not receive false matches.

### Real-time discrete-event runtime

Future actions are persisted in SQLite as due times, not pre-generated messages.
The model is called only when a REPLY or INITIATE becomes due. Closing and
reopening the application does not erase pending events; missed due events can be
recovered. Generated messages are stored as `SIMULATION`, never reclassified as
`REAL` evidence.

The core never sends a message to KakaoTalk, Instagram, email, or any other real
service. Delivery/integration must remain an explicit product-layer decision.

### Long-term observable memory

- relationship-conditioned language profile;
- topic memory from repeated observable conversation cues;
- event memory from explicit date/time mentions, including simple relative dates;
- raw historical responses withheld from RAG by default.

Event cues are remembered as mentions, not guaranteed facts.

### Provider independence

The replay core depends on the `BurstLanguageModel` contract, not NVIDIA.
Supported adapters include:

- NVIDIA hosted/local NIM;
- generic OpenAI-compatible local endpoints such as LM Studio, llama.cpp, vLLM,
  or compatible local services.

Retrieval can remain dependency-free lexical or optionally blend an
OpenAI-compatible dense embedding provider.

### Privacy boundary

Loopback model endpoints are allowed by default. Sending private conversation
context to a remote generation or embedding endpoint is blocked unless the user
explicitly enables `--allow-remote-private-context`.

Raw archives, local identity maps, SQLite state, and generated artifacts are
ignored by Git.

## Recommended 1.0 workflow

1. Import archives and review identity mappings.
2. Run `backend.replay_audit` to validate timing/action behavior.
3. Run `backend.replay_generate` using a local provider first.
4. Compare Kakao-only and fused evidence on identical held-out cases.
5. Run `backend.shadow_audit` before trusting long-running behavior.
6. Only then integrate `LiveSimulationEngine` into a UI or local application.

## Commands

### SELF twin, local generation

```bash
python -m backend.replay_generate \
  ./data/raw/kakao_bundle.zip \
  ./data/raw/instagram_export.zip \
  ./identity.local.json \
  --self-twin \
  --provider local \
  --model YOUR_LOCAL_MODEL \
  --sources both
```

### PERSON twin, hosted NVIDIA with explicit consent

```bash
python -m backend.replay_generate \
  ./data/raw/kakao_bundle.zip \
  ./data/raw/instagram_export.zip \
  ./identity.local.json \
  person-001 \
  --provider nvidia \
  --allow-remote-private-context
```

### Closed-loop shadow audit

```bash
python -m backend.shadow_audit \
  ./data/raw/kakao_bundle.zip \
  ./data/raw/instagram_export.zip \
  ./identity.local.json \
  CONVERSATION_ID \
  --self-twin \
  --provider local \
  --model YOUR_LOCAL_MODEL
```

## Known limitations that remain valid in 1.0

1. Human behavior is stochastic; exact future text is not a meaningful universal
   target and high replay scores do not imply identity reconstruction.
2. Initiation is harder than replying. Topic/event memory constrains plausible
   continuity but cannot observe an event that never appeared in the data.
3. Event parsing is intentionally conservative and is not a full calendar or
   natural-language temporal reasoner.
4. Dense retrieval quality depends on the selected embedding model and must be
   validated against the lexical floor on held-out data.
5. Sparse relationships fall back to broader persona/timing statistics.
6. Kakao exports cannot recover true second-level timestamps.
7. The live runtime is a local simulation engine, not a finished mobile/desktop
   messenger UI.

Those are product/research boundaries, not hidden claims deferred to a later
version.
