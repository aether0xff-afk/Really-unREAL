# Really-unREAL v1.2.0

Really-unREAL 1.2 is a behavior-runtime release. It fixes the structural issues found after live testing 1.1.1 rather than adding another cosmetic chat feature.

## Real silence: REPLY vs WAIT

A user message no longer guarantees that a reply eventually exists. Live mode first makes a relationship/context-conditioned `REPLY` vs `WAIT` decision. Complete historical counterpart bursts provide response/silence evidence, while the right-censored end of an export is not treated as a fake ignore.

## Action semantics

The runtime now separates:

- `WAIT` — no message behavior;
- `READ` — inferred simulation read event;
- `REPLY` — response to the counterpart;
- `FOLLOW_UP` — another target message inside an active session;
- `INITIATE` — a new-session start after a long idle gap.

Historical Replay no longer uses same-session follow-up as if it were a new initiation. Long-gap target events after the counterpart remain role-ambiguous instead of being force-labeled.

## Read state

`READ` is now independent from `REPLY`, so `읽음 추정` may occur before the modeled reply. The app explicitly keeps this as SIMULATION inference: exported Kakao logs do not provide real read timestamps.

## Better live timing

- adds time-since-last-visible-message instead of relying only on the previous pair gap;
- recognizes common Korean questions without `?`;
- validates action-role consistency before sampling timing;
- keeps the validation-gated hazard model ahead of tiny empirical context cells;
- permits survival mass to remain silent rather than forcing a final one-year event.

## User / target bursts

Rapid user bubbles no longer re-sample the reply clock on every Send. A pending unclaimed reply keeps its sampled behavior time with only a short input-settle floor.

Generated target bursts use observed REAL internal bubble spacing when available instead of a fixed `+1 second` gap.

## Atomic live runtime

SQLite events now support an atomic `CLAIMED` state.

- the same due event cannot be generated by two windows/processes simultaneously;
- later user messages cannot cancel an already claimed generation;
- provider failures are applied to the exact claimed event;
- stale claims recover after restart;
- generated message insertion and event completion happen in one transaction;
- resetting a conversation while generation is in flight prevents stale output from returning.

Provider retry clocks remain separate from immutable modeled behavior time and retries remain causally cut off at that behavior time.

## Generation anti-copy hardening

Long historical exemplar reuse is checked with both n-gram Jaccard and containment. If repeated candidates stay too close, the final attempt removes raw historical response wording entirely and generates from style/burst/current-context evidence only. Short common expressions remain allowed.

## Evaluation

- timing is evaluated even when the LLM/provider fails for that case;
- mean-like metrics use Student-t intervals for small samples;
- binary match rates use Wilson intervals;
- the default NVIDIA 3-case run remains labeled as a smoke check.

## Privacy / interpretation

- REAL and SIMULATION remain separate;
- `읽음 추정` is not a real Kakao receipt;
- hosted private-context inference still requires explicit consent;
- no real messaging-platform send API is used;
- the base LLM remains a general model conditioned by person-specific observable evidence, not a neural reconstruction of a person.

## Windows artifact

The guarded release workflow runs the full regression suite, imports the integrated 1.2 runtime, builds the PyInstaller one-file Windows app, executes the packaged `--smoke` path, packages `Really-unREAL-v1.2.0-Windows-x64.zip`, and publishes the GitHub Release. Hosted NVIDIA availability remains a separate informational external-health signal rather than artifact correctness.
